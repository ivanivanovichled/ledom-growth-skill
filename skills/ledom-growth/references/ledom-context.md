# Контекст и доказательства LEDO.М

## Устойчивый контекст

- Бренд: LEDO.М. Основной публичный сайт: https://ledo-m.ru/; CMS: Tilda.
- Рабочий сегмент: бизнес/премиум, ремонт квартир в Москве и Московской области. Смежные услуги, ИЖС, технадзор или проектирование включать только при подтверждении актуальным предложением и задачей.
- Разделять собственника квартиры, дизайнера/архитектора и иные сегменты. Боль и критерии выбора не считать установленными без разговоров, реальных отзывов, обращений или другого источника.
- Рабочие гипотезы для исследования: предсказуемость состава сметы, качество реализации дизайн-проекта, контроль скрытых работ, взаимодействие подрядчиков, ответственность за изменения. Проверять, какие из них важны конкретной аудитории.
- Премиальность раскрывать конкретикой работы и доказательствами. Не превращать её в обещание отсутствия рисков, «лучший ремонт» или скидочную кампанию.

## Источники проекта

Сначала искать через `rg` по нужной теме, не читать весь архив. Использовать фактический корень проекта.

| Что нужно | Куда смотреть |
|---|---|
| Действующие полномочия, оформление, очередь и ограничения | `AGENTS.md` |
| Услуги, факты и реальные примеры | Официальный Tilda MCP, публичные страницы, подтверждённые материалы владельца |
| Планы/дубли/выпуск | `docs/`, свежий список Tilda, `/blog`, sitemap; `PAGES.json` только как локальный указатель |
| Активная серия приёмки | `docs/ACCEPTANCE-PUBLICATION-QUEUE-2026-11-02.md` и `.json`, если существуют; сверить свежие журналы, не закреплять в навыке исторические номера/остатки |
| Реклама/лиды | `реклама, Яндекс Директ и маркетинг.md`, фактические отчёты Метрики/CRM |
| Нормативные факты | `Технический надзор/Нормативная_база_технического_надзора.html`, `Библиотека/Каталог_нормативов.html`, `Реестр_нормативов.json` и порядок ведения библиотеки; читать актуальные правила сверки |
| Ранее отправленные письма | Журналы в `docs/`, поиск по почтовому ящику, ветки и Sent |

Не переносить цифры из дизайнерского КП в цены для конечного заказчика. Тариф партнёрского вознаграждения, стоимость ремонта, бюджет объекта и цена работ — разные величины. Число проектов, сроки и гарантии использовать только с актуальным подтверждением и точным смыслом.

## Исследование клиента

Для каждой аудитории выделить: событие начала поиска, что сравнивала, почему выбрала/отказала, что мешало обратиться, какие доказательства требовались. Отделять слова клиента от собственной интерпретации. Не превращать несколько отзывов в статистику рынка и не придумывать интервью.

В рабочем реестре хранить: утверждение → источник/дата → тип доказательства → разрешённая формулировка → ограничения. Для публичного GitHub не включать реальные обращения, почтовые журналы, индивидуальные сметы, внутренние файлы, выгрузки или неподтверждённые бизнес-цифры.

Существующая проектная база важнее нового дублирующего «маркетингового контекста». Создавать отдельный brief только когда он помогает выполнить конкретную задачу; шаблон — `templates/campaign-brief.md`.
