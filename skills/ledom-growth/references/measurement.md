# Измерение продвижения и качества обращений

## Сначала определить событие

Для каждой цели записать бизнес-смысл, точный триггер, получателя данных и проверку. Использовать текущие счётчики, цели и интеграции; не устанавливать новый стек аналитики по умолчанию.

| Этап | Что он доказывает |
|---|---|
| Клик CTA/телефона/мессенджера | Намерение взаимодействовать; не состоявшееся обращение |
| Форма показывает success | Клиентская часть сообщила об успехе; не получение приёмщиком |
| Заявка у приёмщика | Подтверждённая техническая доставка; может быть тестом/спамом |
| Валидный контакт | Реальный контакт, без дубля и теста |
| Квалифицированное обращение | Соответствует согласованным услуге, географии, объёму и другим критериям |
| Встреча/смета | Следующий фактический этап обработки |
| Договор/выручка | Подтверждённые договор/финансовые данные; не прогноз по кликам |

Критерии квалификации не придумывать. Если бюджет/минимальная площадь/состав неизвестны, отметить зависимость; не отбрасывать обращения по вымышленному порогу.

## Источники и атрибуция

Метрика — источники/поведение/цели; Яндекс Вебмастер и GSC — данные запросов, страниц и индексирования; CRM/учёт — статусы и договоры. Сверять период, регион, устройство, модель атрибуции и различия систем. Средняя позиция не является проверенной позицией конкретного московского пользователя.

UTM для партнёров/платных размещений фиксировать до выпуска: source=площадка, medium=тип размещения, campaign=проект кампании, content=вариант/позиция. Не добавлять UTM к внутренней перелинковке. Не передавать имена, email, телефоны и другие персональные данные в UTM/URL событий. Хранить чувствительные выгрузки вне публичного пакета навыка.

## Расчёты

- Считать из исходных строк скриптом/таблицей, сверять итог независимо по группам. Фиксировать правила дублей, исключений, часовой пояс Europe/Moscow и границы периода.
- Тестовые заявки, повтор одного обращения, спам и неизвестный статус отдельно. Успех теста не коммерческий лид. Открытую квалификацию и незавершённую сделку не считать отказом.
- Конверсия сайта: выбранные подтверждённые обращения / сопоставимая аудитория за тот же период, при согласованной атрибуции. Не делить лиды одного источника на все визиты.
- CPQL: относимый расход / квалифицированные обращения. При нуле знаменателя — «не определено», не ноль. Расход за полный месяц не делить на заявки за неделю.
- Для длинного цикла различать календарный отчёт и когорту привлечения: договоры текущего месяца могут относиться к старым обращениям. Незрелую когорту отмечать как незавершённую; не обещать срок окупаемости без данных.
- Для органики учитывать содержание затрат (контент/разработка/размещения), не называть её бесплатной. ROI/ROMI не выводить только из выручки без согласованного определения затрат и маржи.

Если просят отчёт по выгрузке лидов, можно использовать `scripts/funnel_report.py`: он принимает снимок одной строки на лид, проверяет дубли, исключает тесты и выводит счётчики по источникам. Это описательный отчёт по когорте создания, не доказательство причинности или окупаемости. Формат и пример запуска указаны в справке скрипта.

## Управление гипотезами

У каждой гипотезы: наблюдение/источник → изменение → ожидаемый измеряемый результат → окно наблюдения → условие решения. При малом потоке не делать вид, что A/B-тест статистически надёжен; использовать интервью/проверку сценария и последовательные наблюдения с оговорками. Не менять настройки аналитики без предусмотренного задачей полномочия. Проверить actual receiver/form после разрешённого теста.
